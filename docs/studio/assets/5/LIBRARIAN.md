# Proposed Librarian and UI requirements

All Librarian behavior is **proposed, unimplemented**. No AI provider or paid API is selected or invoked. Use deterministic rules first; owner must authorize any later AI metadata processing and permitted context.

Keep original filename verbatim in protected provenance. Suggest display names using `{subject}-{purpose}-{variant}` and export names `{safe-display-name}__v{sequence}.{verified-extension}`; stable asset/version IDs remain independent. Synthetic example: `blue-circle-poster__v2.png`. Missing subject falls back to `untitled-asset-{short-id}`. Collision suffixes distinguish exports; same-name upload never overwrites existing bytes or implies same identity.

Normalize display whitespace and Unicode; cap lengths according to an owner-approved limit; strip unsafe export characters and reserved platform names. Never derive storage paths from names. Preserve original extension provenance, but export extension follows verified media. Human rename changes display metadata, not original filename, version ID, bytes, or ancestry.

Proposed metadata fields: title, description, tags, section, usage/purpose, media attributes, rights/source/license declaration, creator, project, created time, review state and operation lineage. Each inferred field stores `source=rule|model|human|file`, timestamp, actor/tool/version, confidence where meaningful, and accepted/rejected state. Verified byte facts (hash/dimensions) cannot be overwritten by AI text. Human corrections take priority and survive regeneration; suggestions never silently replace accepted values. Unknown rights remain unknown and may block export under owner policy.

Organization uses virtual sections/collections and filters, not physical moves. The original and versions remain one asset timeline with explicit parent links. Review and approval target exact versions. Existing Files sections require a mapping decision; do not redefine their meaning or move legacy files. Suggested duplicate detection uses project-local hashes for human review only; never automatically merge, delete or disclose another project's asset.

Search proposal: project-authorized title/display/original filename, accepted tags, description, section, media, creator, dates and review filters. Index accepted fields with normalized matching; inferred suggestions are opt-in and visibly labeled. No cross-project context, embeddings or search counts by default. Ranking should favor exact names, then accepted tags, then description; pagination remains stable and permissions precede scoring. Owner must choose index update latency, language rules and any semantic-search provider. Tombstones and revoked records must leave searchable views promptly under the approved policy.

Tyler interface contract: visible project destination, asset and selected version, Original badge, parent/operation provenance, metadata suggestion approval, human edit, review status, upload progress/resume/cancel, explicit download target, and upscale-as-new-version action. Provide loading, empty, offline/stale, forbidden, conflict, quota, failed job, cancelled, and unsaved states with keyboard focus and long-name handling. Switch project clears scoped selection and pending results; ask how to handle active upload before switching without silently redirecting it. Explain that an upscale may alter details and needs human review.

Wait for selected owner-approved design tokens/components before integrated UI. Architecture drafting continues independently. Shared renderer, preload, main/API, packaging and backend implementation require separate approved assignments.
